# v0.3.0 · Field control panel: cameras, radar, GPS, data collection

<img src="https://raw.githubusercontent.com/CosminBMemetea/querra-fence/52b4a8413044f5ebf9f00f23bab64feca285eb16/docs/img/panel-desktop.png" width="720" alt="QUERRA field panel on a laptop (captured at v0.5.0; GPS position blurred)">

A web dashboard on the Jetson for the field. Open it on a phone on the hotspot or on a laptop, see every sensor live,
and start or stop data collection with one button. The screenshot was taken at v0.5.0, which added the ROS 2 card,
and the GPS position is blurred.

**Models:** field mode runs **model-v0.3** as a TensorRT FP16 engine, and the panel can switch to model-v0.2.

## Highlights

- **Both cameras live:** the USB Arducam and the CSI IMX219 as MJPEG, 640 px at about 10 fps each. A grey-world white
  balance corrects the CSI camera's magenta cast.
- **LD2450 radar:**
  - a ±60°, 6 m fan with up to 3 targets and their trails;
  - distance, angle and speed per target;
  - fps, frames, bad frames, errors and the demo flag.
- **GPS:** fix type, satellites used and seen, HDOP, position with a map link, altitude, speed, heading and the time
  since the last fix.
- **Data collection:**
  - a big Start and Stop;
  - run name, elapsed time, frames, fps, size, alerts, disk left and the last detections;
  - after Stop, the page says when it is safe to power off.
- **Settings:** start at boot (off by default), the detector engine, the Vision demo on or off, and safe shutdown.
- **History:** confirmed alerts with Google Maps links, and recent runs with a streamed `.tar.gz` download.
- **Interface:** English and Polish, a dark layout for phones and laptops, and no CDN, so it works offline on a hotspot.

## Architecture

| Part | How |
| --- | --- |
| Cameras | `hub.py` inside the panel is the only owner of both cameras. GStreamer opens them on demand and closes them 20 s after the last viewer. |
| GPS | `gpsd` owns the u-blox port, and the hub is a gpsd client. |
| Radar | The `ld2450-radar` service owns `/dev/ttyUSB0`. The panel relays its SSE stream at `/radar/events`, because the service sends no CORS headers. |
| Field mode | `field.sh` reads full-size USB frames from the hub over QFC1 on `127.0.0.1:5602`, the simulator's protocol, with the gpsd fix in each frame header. Without the hub it opens the camera and the GPS itself. |
| Detection | YOLO11n [model-v0.3](https://github.com/CosminBMemetea/querra-fence/releases/tag/model-v0.3) as a TensorRT FP16 engine. An alert needs 5 of the last 8 frames to agree on a GPS position within 5 m. |

Stack: Python standard library `http.server`, plus the GStreamer, OpenCV and NumPy that ship with JetPack, and one
HTML file.

## Install or run

```bash
cd ~/querra-scout-20261107/panel && ./restart.sh
```

Then open `http://mmx-desktop.local:8080` (or `http://<jetson-ip>:8080`). The panel starts at boot from a user
crontab line tagged `# querra-panel`, and it never starts data collection by itself. The code is in
[`jetson/panel/`](https://github.com/CosminBMemetea/querra-fence/tree/v0.3.0/jetson/panel). The attached archive is a
snapshot of it.

## Known limits

- The radar's firmware and mode show "n/a (read-only)", because the sensor's RX wire is not connected.
- No PIN by default. Anyone on the hotspot can open the panel. A PIN can be set in `config.json`.
- The Vision demo and the recorder take both cameras while they run, so the live view pauses.
